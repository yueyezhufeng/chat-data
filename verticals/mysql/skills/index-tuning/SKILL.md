# 索引调优流程

## 前置（缺一不可）

1. 已按 slow-query-triage 确认头号嫌疑查询。
2. `get_table_info` 确认目标列上没有覆盖相同列的既有索引（有就不加，直接说明）。
3. 索引列的选择依据是执行计划里的过滤/排序条件（`WHERE` 等值列在前，`ORDER BY` 列在后），不是感觉。

## 提交

- `stage_index_change` 提交：表、列（按顺序）、一句话理由。
- 提交后向用户说明三件事：变更内容（SQL 原文）、它现在只是暂存、DBA 需要在审批面点「批准」。

## 红线

- 你不能应用变更，也不能承诺何时生效。批准是人的动作。
- 护栏会拒绝重复索引、超宽索引和白名单外的表——被拒时把原因如实转达。
- 应用后系统会在变更卡片上自动给出"整改后实测耗时"；那一刻之前不要预测性能数字。
